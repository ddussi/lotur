## 완료 조건

- [x] G1 요청 격리: HTTP·WebSocket의 전송 메타데이터를 공통 프로토콜 규칙으로 검증한다. 헤더 경계값·잘못된 경로를 거부한 뒤에도 같은 터널의 기존 스트림과 후속 요청이 정상 동작한다.
- [x] G2 접근 정책: 최초 접근과 주기적 재검사가 같은 공유 접근 정책을 사용한다. DEVELOPER, REVIEWER, 복합 역할의 SSE·WebSocket은 유지되고, 계정 비활성화·실제 권한 회수는 연결을 종료한다. authVersion·비밀번호 변경 요구 검증을 유지한다.
- [x] G3 이벤트 일관성: 같은 revision·경로의 미커밋 이벤트를 커서가 추월하지 않는다. 실제 PostgreSQL의 제어된 동시 트랜잭션과 재연결로 누락 없는 전달을 검사한다. 최초 목록·답글·집계·커서의 읽기 스냅샷을 통일하고 보관 기간 초과 커서의 재동기화를 명시한다.
- [x] G4 화면 상태: bootstrap을 타입 검사 가능한 모듈로 작성하고 기존 URL의 단일 번들로 제공한다. API/SSE, 서버 데이터, 초안, 렌더링, 수명 관리를 분리한다. 댓글·답글 각각 100개 초과 및 이전 페이지에서 수정·삭제·상태 변경을 반영한다. 다른 사용자의 이벤트·추가 로딩·API 실패 때 초안과 포커스를 보존하고, 제출 중 새로 쓴 글도 보존한다.
- [x] G5 책임 분리: Gateway의 세션 수명, 스트림 전송, 접근·운영 정책, 서버 조합 책임과 상태·자원 소유권을 명확히 한다. transport epoch 및 종료 정리를 유지한다. 두 리뷰 저장소의 동일한 변경 판단을 순수 정책으로 공유하고 PostgreSQL 판단은 잠금 안에서 실행한다.
- [x] G6 구조 보호: proxy·operations 및 순수 정책 모듈의 의존 경계를 검사한다. 리뷰 비활성화 상태에서 기본 중계가 독립적으로 동작한다.
- [x] G7 호환성: 기존 Carrier/Client, 인증 쿠키·토큰, 프로젝트·revision·댓글 데이터, bootstrap URL, Vite/Next 통합, 이벤트·페이지 API를 유지한다. 필요한 API 확장은 기존 사용을 깨뜨리지 않는다.
- [x] G8 최종 검증: 스타일·타입·경계·빌드·스크립트·애플리케이션·실제 PostgreSQL·Vite/Next 브라우저 검사가 모두 통과한다. 운영 HTTPS 검증은 사용 가능한 승인된 환경에서만 수행하고 불가능하면 범위를 명확히 기록한다.
- [x] G9 보고: 각 조건의 변경 파일·회귀 테스트·실행 결과·제한을 기록하고 고2 수준 설명을 덧붙인다.

## 작업 원칙

각 문제를 실패하는 테스트로 고정한 뒤 최소 수정과 구조 정리를 수행한다. 같은 변경 이유와 불변식을 갖는 로직만 공유한다. 상태 전이와 판단은 순수 함수로, DB 잠금과 전송 등 부수효과는 명시적 경계에 둔다. 안정성 수정 자체를 선택적 기능으로 만들지 않는다.

## 실행 기록

- 시작 시 작업 트리 깨끗함. 목표 등록 후 G1·G2의 회귀 테스트부터 진행한다.

- G1·G2: 실패 재현 후 공통 메타데이터 검증과 공유 접근 정책으로 수정. 기존·후속 HTTP/SSE/WS 보존 및 실제 권한 회수 검사 통과.

- G4: 타입 기반 단일 bootstrap, API/페이지/초안/SSE 모듈 분리. 오래된 페이지·늦은 응답·실시간 이벤트·제출 중 입력·실패 보존 브라우저 검사 통과.

- G7·G8: 최종 `npm run check` 종료 코드 0. 스크립트 53개, 앱·패키지 349개(실제 PG 17개 포함), 브라우저 9개 통과. 실패·건너뜀 0. 스타일·타입·경계·빌드·diff 검사 통과.
- 중간 전체 검사에서 기존의 실시간 60/100ms 권한 만료 테스트가 병렬 부하로 실패했다. 테스트에 시계를 주입하고 정확한 만료 이벤트를 기다리도록 바꾼 뒤 전체 검사를 다시 통과했다.

- 검증에 사용한 이번 목표 전용 PostgreSQL 컨테이너를 종료했다. 커밋·push·운영 배포 없이 결과를 현재 작업 트리에 남겼다.
