# Review Tunnel v0.1.0-alpha.1

First alpha for small teams that trust one another and operate their own Gateway. Share a local web app and review it with page comments, responsive pins, filters, a persistent inbox, internal notifications and re-review requests/results.

## Try and install

- Run the [local demo](https://github.com/ddussi/lotur/blob/v0.1.0-alpha.1/docs/local-demo.en.md) with Node.js 24+, Docker and Chrome. It creates isolated synthetic accounts and a persistent demo database on your computer; no domain or certificate is needed.
- Install the attached `review-tunnel-client-0.1.0-alpha.1.tgz` on a developer's computer with `npm install --ignore-scripts <archive-path>`, then run `npx --no-install review-tunnel --version`. See the [Client guide](https://github.com/ddussi/lotur/blob/v0.1.0-alpha.1/docs/client-installation.en.md) for login and sharing. Vite and Next integration archives are attached separately.
- Verify downloaded source and package files against `SHA256SUMS` and `release-manifest.json`. The three package archives, source archive, license and changelog share the manifest's exact source commit. These are GitHub release archives; no npm registry package is required.
- Runtime images are provided for `linux/amd64`: Gateway, Admin CLI, Client, canary, database backup and database restore. `images.json` lists the immutable references and `release-image-tags.json` maps them to this version. Verify `images.json` against `images-SHA256SUMS`. Follow the [Linux installation guide](https://github.com/ddussi/lotur/blob/v0.1.0-alpha.1/docs/linux-deployment.md) for a hosted deployment.

## Data and upgrades

Migration 18 preserves the deployed event-retention change; migrations 19–21 add the re-review workflow and notifications. The upgrade checks also cover the older local development schema that used overlapping numbers. Existing review contents, pins, replies, notifications and migration timestamps are preserved by those tested upgrade paths.

Read the [upgrade and restoration guide](https://github.com/ddussi/lotur/blob/v0.1.0-alpha.1/docs/upgrading.en.md) before updating. Back up while writes are stopped, preserve the old configuration and immutable images, and allow for Gateway restart ending active share URLs. Database grants and login roles need explicit reapplication after restoring a dump. An application rollback does not undo DB changes, and arbitrary older images are not supported rollback targets without a compatibility check.

## Validation and limits

The selected candidate's CI and attached sanitized records identify its exact source, runtime images, package checksums, installed notices and restoration results. Validation covers application/PostgreSQL behavior, permissions, concurrent edits and in-tab drafts, Vite/Next browsers, the local demo, standalone Client installation, six Linux runtime images and restoration into a new database. Read the records for the actual versions and counts; a synthetic drill is not a production recovery-time guarantee.

The demo and source were exercised on macOS and Linux with Chrome. Published images are `linux/amd64`; native Windows, other browser engines and published ARM images are not established by this release. Review authorization is deployment-wide, not project membership: this alpha is unsuitable for mutually untrusted customers sharing one Gateway. Drafts stay in the current tab's memory, not across reloads. Live tunnel routes do not survive a Gateway restart. Multi-Gateway/high-availability operation, public signup, external email/Slack notifications and npm registry publication remain outside this release.

Report vulnerabilities through the [private reporting form](https://github.com/ddussi/lotur/security/advisories/new); see the [security policy](https://github.com/ddussi/lotur/blob/v0.1.0-alpha.1/SECURITY.md) for supported versions and trust boundaries.
