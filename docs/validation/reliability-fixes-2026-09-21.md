## 호환성과 적용 시 주의할 점

- F03의 송신 전 검사는 Client에 있다. Gateway만 갱신해서 구형 Client의 잘못된 응답 전송까지 해결했다고 볼 수 없다. 새 Client 아카이브와 Gateway를 함께 검증·배포해야 한다.
- 헤더 한도를 임의로 늘리거나 헤더를 잘라 보내지 않는다. 정상 데이터의 wire 형식과 v1 decoder 계약은 유지한다. Upgrade 전 오류는 이제 빈 연결 종료 대신 502가 된다.
- `RESUME_IN_PROGRESS`의 재시도 hint와 기존 재연결 정책은 유지한다. `RELAY_NOT_READY`를 새로운 자동 재시도 대상으로 만들지 않았다.
- 삭제된 댓글에 과거 버전이 이미 저장한 답글을 자동 정리하지 않는다. 이번 변경은 이후 쓰기의 상태 계약을 고친다. 운영 데이터 보정은 별도 확인이 필요하다.
- 역슬래시가 들어 있는 과거 댓글은 본문을 유지하고 focus 이동만 거부한다. 인코딩된 `%5C`와 문자 그대로의 역슬래시는 구분한다.
- F06은 배포 작업자 코드 변경이다. 실제 적용 시 [자동 배포 안내](../automatic-deployment.md)에 따라 서버의 검토된 작업자 파일을 갱신해야 한다. 기존 hash 일치 검사를 우회하지 않는다.

## 검증 한계

저장소가 지정한 PostgreSQL 17.11 이미지는 로컬에 없었고, 재시도한 pull도 약 2분간 진행 출력이 없어 해당 실행을 종료했다. 기존에 설치된 17.6 digest를 임시 override로 사용했으며 저장소의 17.11 설정은 바꾸지 않았다. 따라서 이 기록은 17.11 검증을 대신하지 않는다.

수정 브랜치를 push하지 않았으므로 원격 Linux CI의 새 성공 결과는 없다. 여섯 런타임 이미지 재빌드·복원, demo 전체 수명 검사, 운영 HTTPS, 이전 앱/새 schema 조합, 장기 부하·다른 OS/브라우저는 이번에 재실행하지 않았다. DB·프로토콜 버전·의존성은 유지했고 변경 경로에 대한 전체 로컬 gate를 실행했다.

검증 후 이 작업이 만든 Compose 프로젝트 `lotur-fixes-20260921`의 PostgreSQL과 전용 네트워크를 제거했고 해당 이름의 실행 컨테이너가 없음을 확인했다. 기존 사용자 서버·다른 프로젝트 DB·볼륨은 유지했다. 최종 diff의 공백 검사와 변경 문서의 로컬 링크·코드 블록 검사도 통과했다.

## 이력에 남길 수 있는 증거

본인의 실제 기여 범위와 함께 다음 사례를 설명할 수 있다. 아래 수치를 운영 성능으로 확대하지 않는다.

- 합성 1만 댓글의 필터 경계 재현에서 전체 이력 재조회를 100회에서 최대 2회로 제한하고, 실제 브라우저에서 입력 중인 초안을 보존했다.
- origin 응답 오류 한 건이 전체 터널을 끊는 반례를 HTTP·WebSocket으로 검증하고, 다른 SSE·WebSocket·후속 HTTP 요청이 유지되도록 수정했다.
- 삭제와 답글의 PostgreSQL 경합을 재현해 저장소 계약을 일치시키고, 실패한 변경이 이벤트·알림을 남기지 않음을 확인했다.

실제 사용자 리뷰 시간, p95 지연, 처리량·메모리, 운영 장애율 개선은 아직 측정하지 않았으므로 성과 수치로 사용하지 않는다.
