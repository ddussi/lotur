# Review Tunnel 구현 현황

- 갱신일: 2026-09-09
- 구현 기준: `41e9570` — 서버 구조와 리뷰 기능 통합 후 Linux CI 경로 수정까지 포함
- 배포 상태: 해당 커밋의 CI·이미지 게시·배포 성공을 확인했다. 이는 최초 오픈소스 릴리스 게시와는 별개다.
- 배포 형식: 현재는 소스 checkout 또는 직접 빌드한 Docker 이미지. 설치용 Client와 로컬 체험 환경은 [알파 공개 준비 계획](open-source-alpha-plan.md)에 따라 준비 중이다.

| 알림 | 참여자 멘션·답글·재검토 회차별 수신자 알림, 전체 프로젝트의 내 알림, 읽음 처리와 커서 페이지 |

| 동시 수정·초안 | 변경 버전 충돌 표시, 이벤트 재동기화, 제출 중 추가 입력·실시간 갱신·필터 변경에서 현재 탭의 초안 유지 |

재검토 요청을 새로 만들려면 migration 19–21과 `REVIEW_WORKFLOW_ENABLED=true`가 필요하다. 기본값은 꺼짐이다. 자세한 순서는 [리뷰 사용 안내](internal-review-guide.md#운영-환경에서-재검토를-켜는-순서)와 [English review guide](review-guide.en.md#enable-re-review-as-an-operator)를 따른다.

## 지원 범위와 제한

- `DEVELOPER`와 `REVIEWER`의 콘텐츠·리뷰 접근은 배포 전체에 적용된다. 프로젝트·버전별 목록은 접근 권한 목록이 아니다. `ADMIN`만 있는 계정은 공유 콘텐츠를 볼 수 없다.
- 하나의 Gateway를 운영하는 구성을 기준으로 한다. DB는 계정·리뷰·운영 상태를 저장하며 실행 중인 터널을 여러 Gateway에 분산하지 않는다.
- 초안은 현재 탭의 메모리에 있다. 새로고침·탭 종료·다른 기기를 넘어서 저장하지 않는다.
- 고유 요소 ID가 없는 핀은 원래 화면 크기를 바탕으로 한 근사 좌표다. 앱 URL의 query/hash, iframe 내부·Shadow DOM 내부 대상, 텍스트 구간, 스크린샷은 저장하지 않는다.
- 프로젝트별 초대·접근 제어, 외부 알림, revision 사이의 자동 댓글 이관, 전체 편집 이력은 후속 범위다.
- 유지보수자가 제공하는 공개 Gateway·도메인·가입 서비스는 없다. 로컬 체험 환경도 다른 컴퓨터에 대한 무인증 공유 서비스로 사용하지 않는다.

권한과 네트워크 경계는 [보안 정책](../SECURITY.md), 실제 사용은 [한국어](getting-started.md)·[English](getting-started.en.md) 시작 안내를 따른다.
