# 작은 팀의 리뷰 사용 안내

2026-09-08 구현 기준. 앱 화면의 리뷰 패널과 Control 주소의 `/reviews` 리뷰함을 함께 사용한다.

**검토자는 문제를 적고, 개발자는 수정하고, 검토자는 다시 확인한다.**

1. 공유된 앱에서 댓글이나 핀을 남긴다. 패널이 화면을 가리면 닫고, 오른쪽 아래 버튼으로 다시 연다. 모바일은 처음에 패널이 닫혀 있다.
2. `미해결`은 아직 작업이 남은 댓글이다. `내가 시작한 리뷰`로 내가 남긴 것만 찾을 수 있다. 리뷰함에서는 버전과 페이지 경로도 선택할 수 있다.
3. 개발자는 답글을 남기고 `Request review`를 누른다. 상태가 `Needs review`로 바뀌며 원댓글 작성자에게 알림이 간다. 이 단계에서도 답글을 주고받을 수 있다.
4. 원댓글 작성자는 `Confirm resolved`로 해결을 확인하거나 `Request more changes`로 추가 수정을 요청한다. 요청한 개발자는 결과 알림을 받는다. 간단한 작업은 개발자가 바로 `Resolve`로 끝낼 수 있다.
5. 리뷰함의 댓글 상세에서 처리 기록을 확인한다. 기록은 댓글을 실시간 갱신하는 임시 이벤트와 별도로 저장된다. 화면에는 최근 100개를 표시한다.

**앱이 꺼져 있어도 대화는 남는다.**

댓글의 `Permanent link` 주소를 복사하면 리뷰함의 같은 댓글을 다시 열 수 있다. 로그인하지 않았다면 로그인 후 그 댓글로 돌아온다. 앱이 꺼져 있어도 댓글·답글 조회와 허용된 편집은 가능하다. `앱에서 보기`는 같은 프로젝트·버전으로 현재 Gateway에서 실행 중인 공유만 표시한다.

앱 이동은 저장된 페이지 경로와 댓글을 복원한다. 검색 조건이나 해시로만 구별되는 앱 화면의 상태까지 복원하지는 않는다. 원래 URL의 검색어·토큰 등을 리뷰 데이터로 수집하지 않는다. 다른 Gateway에서만 실행 중인 공유는 이 목록에서 확인할 수 없다.

**초안은 현재 탭 안에서 보관한다.**

실시간 갱신, 패널 접기, 필터 변경, 앱 안의 페이지 이동 중에는 초안을 유지한다. 다른 사람이 먼저 고친 댓글은 최신 내용을 보여 주고 내 입력을 남겨 둔다. 내용을 비교한 뒤 `Use latest version and keep draft`를 선택하고 저장한다. 탭을 새로고침하거나 닫으면 초안은 사라진다. 서버에 저장된 댓글과 초안은 다르다.

**알림은 내가 참여한 작업을 찾는 데 쓴다.**

- `@`를 쓰면 이 버전에서 이미 참여한 사람과 프로젝트 소유자 중 멘션 대상을 고를 수 있다. 처음 참여하기 전의 팀원은 목록에 없을 수 있다.
- 새 답글은 원댓글 작성자와 기존 답글 참여자에게 간다. 본인에게는 보내지 않으며 같은 답글의 멘션과 겹치면 하나로 표시한다.
- 리뷰함의 `내 알림`은 프로젝트·페이지 전체를 모은다. 50개씩 조회하고 읽지 않은 알림만 볼 수 있다. 알림 링크의 댓글을 정상적으로 읽은 뒤 그 알림을 읽음 처리한다.
- 재검토 확인·보완은 해당 요청 회차에만 연결한다. 비활성화되었거나 리뷰 권한이 없는 작성자에게는 재검토를 요청할 수 없다.

이 버전은 배포 전체의 `DEVELOPER`·`REVIEWER`에게 프로젝트와 리뷰 기록을 보여 준다. `ADMIN`만 있는 계정은 볼 수 없다. 팀 안에서 서로 보이면 안 되는 프로젝트나 외부 초대가 필요하면 프로젝트별 접근 제한을 추가해야 한다.

**운영 환경에서 재검토를 켜는 순서**

1. Admin CLI의 기존 `migrate` 절차로 DB를 이행한다. 새 변경은 migration 19–21이다. 반복 실행할 수 있으며 기존 댓글을 유지한다.
2. 모든 Gateway를 새 상태와 알림을 읽을 수 있는 버전으로 교체한다. 새 구조가 없는 DB는 readiness 검사에서 실패한다.
3. `REVIEW_WORKFLOW_ENABLED=true`로 새 재검토 요청을 켠다. 실제 Gateway 실행의 기본값은 꺼짐이다. 꺼도 저장된 재검토와 처리 기록을 읽고 이미 열린 요청에 답할 수 있다.

상태 변경에는 본문과 별개의 `expectedWorkflowVersion`을 보낸다. 이 값이 없는 구형 요청은 최초 버전 1에서만 허용되며 이후에는 충돌 응답을 받는다. 오래된 화면은 새로고침해야 한다. 기능 사용 가능 여부는 context의 `features`에 들어 있다.

공유 중지 스위치를 켜면 리뷰함은 읽기 전용이 된다. 실제 팀의 두 차례 수정·확인 파일럿과 공개 HTTPS 환경 검증은 배포 후 별도로 진행한다.
