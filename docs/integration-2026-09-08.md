# GitHub 서버 구조와 로컬 리뷰 기능 통합

GitHub `ab44e71`의 서버 구조, 요청 격리, 권한 재검사, 자동 배포를 기준으로 로컬 `db4bbf1`·`14c6cf9`·`dff366a`의 리뷰 기능을 통합했다. 양쪽 커밋을 부모 이력으로 유지하는 merge이며 기존 이력을 다시 쓰지 않는다.

## 보관과 구조

- 로컬 미커밋 배포 작업은 `2990ca4`와 `codex/backup-local-20260908`에 보관했다.
- 원격 기준은 `codex/backup-github-20260908`에 보관했고, 통합 전에 모든 ref를 Git bundle로 별도 보관했다.
- 별도 worktree에서 통합했다. 운영 컨테이너는 개발·검사 중 교체하지 않았다.
- Gateway의 admission, carrier, streams, session, operations, authorization 모듈과 보안 변경을 유지했다.
- `review-ui`의 API·페이지 재검증·초안·실시간 연결 모듈을 유지하고 핀·필터·멘션·인라인 편집·재검토를 이식했다. 리뷰함과 오버레이가 같은 TypeScript 편집 컴포넌트를 번들로 사용한다.
- 기존 자동 배포 workflow와 SSH 배포 작업자는 변경하지 않았다. 로컬의 중복 배포 파일은 최신 원격과 내용이 동일함을 대조하고 하나의 추적 파일로 정리했다.

## DB 변경 충돌

운영에서 확인한 18번은 이벤트 보관 하한 변경이므로 번호와 적용 시각을 유지한다.

| 번호 | 변경 |
| --- | --- |
| 18 | 기존 이벤트 보관 하한 및 만료 cursor 재동기화 |
| 19 | 재검토 상태·workflow version·처리 기록 |
| 20 | 답글 알림 사유·수신자 조회 인덱스 |
| 21 | 재검토 알림·중복 방지 source key·workflow 연계 |

번호 18을 재검토에 썼던 과거 로컬 DB도 지원한다. 보관 하한 테이블의 실제 존재 여부를 확인해 초기화하고, 추가 변경을 반복 실행해도 기존 리뷰·답글·알림과 migration 적용 시각을 유지한다. 이전 양쪽 schema를 고정 fixture로 보관해 실제 PostgreSQL 업그레이드를 검사한다.

배포 전 운영 리뷰 5개, 답글 1개, migration 18개를 확인했고 서버에 DB dump·현재 환경·배포 상태를 별도로 백업했다. 백업 아카이브의 목차를 검사했다. 개인정보와 운영 접근 정보는 저장소에 넣지 않는다. 새 재검토 요청은 migration 완료 후 새 Gateway에서 `REVIEW_WORKFLOW_ENABLED=true`로 활성화한다.

Node.js 24.12.0, 격리된 PostgreSQL 17.6, 로컬 Chrome에서 실행했다.

GitHub Linux 검사에서 발견한 macOS 전용 스크린샷 경로 2곳도 Playwright의 테스트별 결과 경로로 변경했다.

통합 중 이벤트가 모두 정리된 feed의 cursor 보존과 필터 쿼리를 수정했다. 기존 브라우저 회귀 검사는 새 기본 미해결 필터와 workflow version에 맞춰 명시적으로 전체 필터·현재 버전을 사용한다.

배포는 `main`의 동일 커밋에 대한 GitHub Actions 검사, 이미지 게시, migration, HTTPS canary, 공유 승인 순서로 진행한다. 실제 배포 완료 여부는 해당 Actions 실행과 서버의 `current-release.json`, 컨테이너 revision, readiness를 함께 확인한다. 백업과 이전 컨테이너는 자동 삭제하지 않는다.

초안은 현재 탭 메모리에 보존한다. 새로고침·탭 종료·다른 기기까지 영속하는 기능은 포함하지 않는다. 단일 Gateway 교체 때 기존 공유 연결은 재연결이 필요하다.
